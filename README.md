# Tender Summarizer

Tender Summarizer принимает тендерную документацию в формате PDF и возвращает выжимку через локальную модель Ollama:

```json
{
  "contract_amount": "14 850 000 рублей",
  "deadlines": ["не позднее 30 ноября 2026 года"],
  "contractor_requirements": [
    "наличие действующей лицензии",
    "опыт выполнения аналогичных работ"
  ],
  "penalties": ["пеня в размере 0,1 процента за каждый день просрочки"]
}
```

Все поля обязательны. Если сумма не найдена, `contract_amount` содержит `null`; если в документе нет сроков, требований или штрафов, соответствующее поле содержит пустой список.

## Требования и установка

Для запуска необходимы:

- Python 3.12 или новее;
- [uv](https://docs.astral.sh/uv/);
- установленная и запущенная [Ollama](https://ollama.com/);
- модель из `OLLAMA_MODEL`.

Установка зависимостей и модели:

```bash
uv sync
ollama pull qwen3:8b
```

Ollama и API запускаются в отдельных терминалах:

```bash
ollama serve
```

```bash
uv run uvicorn app.main:app --reload
```

Приложение доступно по адресу `http://127.0.0.1:8000`, Swagger UI — по адресу `http://127.0.0.1:8000/docs`.

## API

`POST /api/v1/tenders/summarize` принимает PDF в поле `file`:

```bash
curl -X POST http://127.0.0.1:8000/api/v1/tenders/summarize \
  -H "accept: application/json" \
  -F "file=@document.pdf;type=application/pdf"
```

Успешный ответ соответствует `TenderSummary`. Заголовок `X-Request-ID` содержит идентификатор запроса.

Ошибки возвращаются в едином формате:

```json
{
  "detail": {
    "code": "PDF_TEXT_NOT_FOUND",
    "message": "PDF does not contain extractable text."
  }
}
```

| Статус | Код | Причина |
| ---: | --- | --- |
| 413 | `PDF_TOO_LARGE` | Превышен допустимый размер загрузки |
| 413 | `PDF_PAGE_LIMIT_EXCEEDED` | Превышено допустимое число страниц |
| 415 | `UNSUPPORTED_PDF_TYPE` | MIME-тип или сигнатура не соответствует PDF |
| 422 | `INVALID_PDF` | PDF пустой или повреждён |
| 422 | `ENCRYPTED_PDF` | PDF зашифрован |
| 422 | `PDF_TEXT_NOT_FOUND` | В документе нет извлекаемого текста |
| 502 | `INVALID_LLM_RESPONSE` | Ответ модели не соответствует `TenderSummary` |
| 503 | `LLM_UNAVAILABLE` | Ollama недоступна |
| 503 | `LLM_CONFIGURATION_ERROR` | Модель или Ollama настроены неверно |
| 504 | `LLM_TIMEOUT` | Истекло время ожидания вызова Ollama |
| 500 | `INTERNAL_ERROR` | Возникла непредвиденная внутренняя ошибка |

Ошибки также содержат `X-Request-ID`.

## Конфигурация

Настройки читаются из переменных окружения и файла `.env`. Пример настроек — [.env.example](.env.example).

| Переменная | Значение по умолчанию | Назначение |
| --- | --- | --- |
| `OLLAMA_BASE_URL` | `http://localhost:11434` | Адрес Ollama |
| `OLLAMA_MODEL` | `qwen3:8b` | Модель Ollama |
| `OLLAMA_TIMEOUT_SECONDS` | `120` | Тайм-аут вызова Ollama, с |
| `MAX_UPLOAD_SIZE_MB` | `20` | Максимальный размер загрузки, МиБ |
| `MAX_PDF_PAGES` | `300` | Лимит страниц PDF |
| `LLM_CHUNK_MAX_CHARS` | `30000` | Размер блока, символов |
| `CHUNK_OVERLAP_PAGES` | `1` | Перекрытие блоков, страниц |

## Логика решения

Обработка PDF:

1. API принимает запрос размером до 20 МиБ при настройках по умолчанию. Лимит применяется до разбора multipart, а размер PDF повторно проверяется после загрузки.
2. Перед обращением к модели проверяются тип и сигнатура PDF, читаемость файла, шифрование и число страниц.
3. `pypdf` извлекает текст по страницам и сохраняет их номера. Нумерация сохраняет порядок текста при разбиении документа. Разбор PDF выполняется в отдельном потоке.
4. PDF без извлекаемого текста отклоняются до обращения к модели.
5. Текст разбивается на блоки с маркерами `[PAGE N]`. Соседние блоки перекрываются по страницам. Если страница больше лимита блока, текст делится по абзацам, предложениям, словам и в крайнем случае по символам. Каждый фрагмент сохраняет номер страницы.
6. Блоки отправляются модели последовательно, чтобы не создавать параллельную нагрузку на локальную модель. Текст документа передаётся отдельно от системных инструкций. Инструкции внутри PDF считаются данными документа и не влияют на правила извлечения.
7. В Ollama передаётся JSON Schema `TenderSummary`, а модель извлекает сумму контракта, сроки, требования к исполнителю и штрафы при `temperature=0`. Ответ валидируется Pydantic. Если сумма отсутствует, используется `null`; если списочных значений нет, используются пустые списки.
8. Результат одного блока возвращается без отдельного объединения. Для нескольких блоков результаты объединяются отдельным вызовом модели. При ошибке сервис не возвращает частичный результат.
9. `TenderSummary` возвращается напрямую. Ошибки Ollama и ответ, не прошедший валидацию, возвращаются как HTTP-ошибки.

### Причины решений

Разбиение по страницам сохраняет привязку текста к исходным страницам. Извлечение по блокам с последующим объединением позволяет обработать документ, который не помещается в один блок, и объединить результаты без предварительного поиска по документу.

RAG не используется, поскольку нужно обработать весь документ. Предварительный поиск может пропустить нужный фрагмент.

## Архитектурные решения

Код разделён на HTTP-слой, сервис и адаптеры. API принимает файл и формирует HTTP-ответы, TenderSummaryService управляет обработкой документа, а адаптеры работают с pypdf и Ollama.

Обработка PDF, разбиение текста и валидация выполняются кодом. LLM используется для извлечения и объединения сведений. RAG и векторная база не используются: задача требует извлечь все требуемые сведения в одном документе, а предварительный поиск может пропустить нужный фрагмент.

Текст документов и ответы модели не логируются. В журнал записываются только служебные данные обработки.

## Тесты

Детерминированный набор не требует Ollama:

```bash
uv run pytest -m "not ollama"
```

Проверки кода:

```bash
uv run ruff check .
uv run ruff format --check .
```

Интеграционный тест использует модель из `OLLAMA_MODEL`; Ollama должна быть запущена, а модель установлена:

```bash
uv run pytest -m ollama
```

Сравнение моделей и результаты описаны в [eval/README.md](eval/README.md).
